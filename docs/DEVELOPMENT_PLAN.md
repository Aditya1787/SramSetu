## Phase 1: Infrastructure, Database Schema & Design System (Steps 1–5)

### Step 1: Flutter Project Initialization, Folder Structure & Dependency Matrix
- **Action:** Initialize Flutter project (`flutter create --org com.sramsetu sram_setu`).
- **Architecture:** Implement Feature-First Clean Architecture (`lib/core/` and `lib/features/`).
- **Dependencies (`pubspec.yaml`):**
  - BaaS: `supabase_flutter: ^2.8.0`
  - State Management: `flutter_riverpod: ^2.5.1`, `riverpod_annotation: ^2.3.5`
  - Navigation: `go_router: ^14.2.0`
  - Models & Immutability: `freezed_annotation: ^2.4.4`, `json_annotation: ^4.9.0`
  - Location & Maps: `google_maps_flutter: ^2.9.0`, `geolocator: ^13.0.0`, `geocoding: ^3.0.0`
  - Media & Utility: `image_picker: ^1.1.2`, `cached_network_image: ^3.4.1`, `intl: ^0.19.0`, `dio: ^5.7.0`
- **Output Artifacts:** `pubspec.yaml`, `lib/main.dart`, `lib/core/router/app_router.dart`.

### Step 2: Supabase Project Setup & Master SQL Migration Script Execution
- **Action:** Provision Supabase project. Execute core DDL migration in Supabase SQL Editor.
- **Tables Created:**
  - `profiles`, `service_categories`, `services`, `service_problems`, `materials`, `service_pricing`, `technicians`, `addresses`, `quotations`, `quotation_items`, `bookings`, `messages`, `technician_locations`, `payments`, `reviews`, `complaints`.
- **Database Indexing:** Create indexes on `bookings(customer_id, status)`, `technicians(is_available, service_category_id)`, `messages(booking_id)`, and spatial coordinates.

### Step 3: Production Row Level Security (RLS) Policy Matrix
- **Action:** Enable RLS on all 16 tables.
- **Policies Implemented:**
  - Customers can read/update only their own `profiles`, `addresses`, `bookings`, and `quotations`.
  - Technicians can read assigned `bookings`, update their own `technicians` availability/location, and write `technician_locations`.
  - Chat access strictly restricted to the customer and technician paired on the specific `booking_id`.
  - Zero access for unauthenticated users.

### Step 4: Storage Buckets Provisioning & Security Policies
- **Action:** Configure 5 storage buckets:
  1. `avatars` (Public reading, authenticated upload).
  2. `service-images` (Public reading, admin upload).
  3. `booking-images` (Authenticated participant read/upload).
  4. `chat-attachments` (Booking participant read/upload).
  5. `technician-documents` (PRIVATE bucket, accessible strictly via Supabase Signed URLs generated by Edge Functions).

### Step 5: Core Design Tokens, Typography & Component Library
- **Action:** Build `lib/core/theme/` and `lib/core/widgets/`.
- **Design System:**
  - Primary Color: Sram Setu Navy (`#0F172A`), Accent Teal (`#0D9488`), Emergency Red (`#DC2626`), Warning Amber (`#F59E0B`).
  - Font Family: Outfit / Inter (Google Fonts).
  - Component Library: Glassmorphism Card, Standard ElevatedButton, Status Badge, Itemized Price Breakdown Table, Shimmer Skeleton Loader.

## Phase 2: Authentication & User Profiles (Steps 6–8)

### Step 6: Supabase Auth Integration & Token Persistence
- **Action:** Implement `lib/features/auth/`.
- **Auth Handlers:** Email/Password authentication, Phone Number OTP verification, and Google OAuth single sign-on.
- **State Management:** `AuthStateNotifier` powered by Riverpod.
- **Auto-Redirect:** `GoRouter` redirect guards routing users based on auth status and profile completeness.

### Step 7: Multi-Role User Profile Onboarding Workflow
- **Action:** Create `lib/features/profile/presentation/screens/profile_setup_screen.dart`.
- **Customer Profile:** Full Name, Phone, Email, Avatar Upload.
- **Technician Profile:** Category selection, Years of Experience, Bank details, Identity document upload (Aadhaar/PAN) to private bucket.
- **Database Trigger:** Postgres trigger automatically creates a row in `profiles` on `auth.users` insert.

### Step 8: Interactive Address Picker & Geocoding Module
- **Action:** Build `lib/features/booking/presentation/screens/address_picker_screen.dart`.
- **Features:** Google Maps widget with drag pin, current location auto-detect using `geolocator`, address geocoding conversion, and saved addresses drawer (Home, Flat, Pincode, City).

## Phase 3: Service Catalog & Upfront Quotation Engine (Steps 9–12)

### Step 9: Dynamic Master Service Catalog & Problem Browser
- **Action:** Build `lib/features/services/`.
- **UI Screens:** Category grid screen (Electrician, Plumber, Carpenter, AC, RO, Appliance), Sub-service browser, and Problem selector screen.
- **Data Fetching:** Realtime cached PostgREST querying with fallback skeleton shimmers.

### Step 10: Natural Language Problem Submission & Media Attachment
- **Action:** Build `lib/features/services/presentation/screens/problem_submission_screen.dart`.
- **Features:** Natural language text input field ("Pankha chal raha hai par speed slow hai"), image picker to upload photos of broken appliances, preferred time slot selector.

### Step 11: Production Itemized Quotation Engine (Edge Function)
- **Action:** Deploy Supabase Edge Function `generate-quotation`.
- **Logic:**
  ```
  Quotation Total = Material Cost + Technician Labour Fee + Visit Charge (₹50) + Platform Fee (₹20) + Emergency Charge (if applicable)
  ```
- **UI Screen:** `lib/features/quotation/presentation/screens/quotation_screen.dart` rendering clean breakdown card with explicit disclaimer (*"No Hidden Charges. Price changes mid-job require your approval"*).

### Step 12: Emergency Quick-Dispatch Workflow
- **Action:** Build 1-tap "Need Help Immediately?" emergency trigger on Home Screen.
- **Logic:** Auto-assigns `is_emergency = true`, applies priority emergency charge, and instantly matches nearest available technician with < 15 minute target dispatch.

## Phase 4: Booking Engine & Geo-Proximity Technician Dispatch (Steps 13–17)

### Step 13: Booking Lifecycle & State Management Engine
- **Action:** Build `lib/features/booking/` state machine.
- **State Stepper:** Enforces strict transition checks across 12 status states (`REQUESTED` -> `QUOTATION_READY` -> `CUSTOMER_ACCEPTED` -> `SEARCHING_TECHNICIAN` -> `TECHNICIAN_ASSIGNED` -> `ON_THE_WAY` -> `ARRIVED` -> `IN_PROGRESS` -> `COMPLETED`).

### Step 14: Technician Portal Dashboard & Online/Offline Switch
- **Action:** Build `lib/features/technician/presentation/screens/technician_dashboard.dart`.
- **Features:** Dynamic online/offline availability toggle button, today's jobs summary, weekly earnings card, rating badge, pending requests list.

### Step 15: Geo-Proximity Technician Dispatch & Ranking Algorithm
- **Action:** Deploy Supabase Edge Function `assign-technician`.
- **Matching Criteria:**
  1. Filter technicians by `service_category_id`.
  2. Filter by `is_available = true` and `verification_status = 'VERIFIED'`.
  3. Calculate distance using Haversine formula (Radius <= 10km).
  4. Rank candidates based on `(Distance * 0.4) + ((5.0 - Rating) * 0.6)`.

### Step 16: Technician Job Request Acceptance Modal
- **Action:** Build full-screen incoming job alert popup for technician.
- **UI Details:** Displays service name, customer distance in km, problem description, estimated payout, and 30-second countdown timer with `[ ACCEPT ]` and `[ DECLINE ]` buttons.

### Step 17: Customer Real-Time Booking Progress Tracker
- **Action:** Build `lib/features/status/presentation/screens/booking_status_screen.dart`.
- **Features:** Live progress step bar, technician profile card (Name, Photo, Rating, Jobs completed), quick `[ Call ]` and `[ Chat ]` action buttons.

## Phase 5: Mid-Job Price Variation & Service Completion Engine (Steps 18–20)

### Step 18: Technician Mid-Job Price Revision Request Workflow
- **Action:** Build `lib/features/technician/presentation/widgets/add_extra_material_dialog.dart`.
- **Use Case:** When a technician opens an appliance and discovers extra broken parts (e.g., motor burned out).
- **Logic:** Technician inputs additional material/labour cost. Status shifts to `EXTRA_WORK_APPROVAL_PENDING`. Work pauses.

### Step 19: Customer Realtime Price Revision Approval & Sign-Off Modal
- **Action:** Build customer modal triggered via Supabase Realtime broadcast.
- **UI Details:** Displays initial estimate (₹320) vs updated requirement (`+ Motor Repair ₹250 = New Total ₹570`). Customer clicks `[ Approve ]` or `[ Reject ]`. Work only resumes upon customer digital approval.

### Step 20: Job Completion Checklist, Final Invoice & Summary Generator
- **Action:** Build job completion workflow. Technician marks work done with photo proof. System generates final PDF/digital receipt stored in Supabase Storage.

## Phase 6: Realtime Engine, Payments & Push Notifications (Steps 21–25)

### Step 21: Supabase Realtime Service Chat System
- **Action:** Build `lib/features/chat/`.
- **Features:** Realtime messaging using Supabase Postgres Changes subscription on `messages` table. Supports text, image attachments, timestamp formatting, and read receipts.

### Step 22: Live Technician Location Tracking & Moving Map Marker Engine
- **Action:** Implement `lib/features/status/presentation/widgets/live_tracking_map.dart`.
- **Logic:** When technician status is `ON_THE_WAY`, background service updates `technician_locations` every 10 seconds. Customer map renders moving technician pin with ETA calculation.

### Step 23: Production Multi-Channel Payment Integration
- **Action:** Build `lib/features/payments/`.
- **Supported Methods:** UPI Deep-linking (GPay/PhonePe/Paytm), Cash on Delivery, and Razorpay/Stripe SDK integration.
- **Security:** Edge Function `verify-payment` validates webhook signatures before marking booking `PAID`.

### Step 24: Ratings, Reviews & Professional Trust System
- **Action:** Build `lib/features/reviews/presentation/screens/review_screen.dart`.
- **Features:** 5-star rating control, tag chips (On time, Professional, Affordable, Clean Work), text review. Postgres trigger updates technician aggregate rating score on submit.

### Step 25: FCM Push Notifications Broadcaster Engine
- **Action:** Deploy Supabase Edge Function `send-notification` integrated with Firebase Cloud Messaging (FCM) HTTP v1 API.
- **Triggers:** Push alerts sent for: `Technician Assigned`, `Technician On the Way`, `Price Revision Request`, `Job Completed`, `Payment Confirmation`.

## Phase 7: Admin Panel, Testing & Production Release (Steps 26–30)

### Step 26: Flutter Web Admin Management Dashboard
- **Action:** Build `lib/features/admin/` compiled for Flutter Web.
- **Modules:** Overview Analytics Cards (Total Revenue, Active Jobs, Verified Technicians, Open Complaints), Booking Audit Table, User Management.

### Step 27: Admin Master Service & Dynamic Pricing Manager
- **Action:** Build administrative CRUD UI for services and materials.
- **Capabilities:** Admin can update material base prices, technician labor rates, visit charges, or add new categories instantly without releasing a new Flutter build.

### Step 28: Dispute Management, Refunds & Customer Support Center
- **Action:** Build `lib/features/admin/presentation/screens/dispute_management_screen.dart`.
- **Capabilities:** Admins inspect disputed bookings, view full message history, review photos, issue partial/full refunds, or suspend non-compliant technicians.

### Step 29: End-to-End Testing & Penetration Audit
- **Action:** Execute comprehensive test suite:
  - Unit Tests (`flutter test`): Test Auth, Quotation calculation, and Booking State Machines.
  - Widget Tests: Validate UI screens and itemized breakdown tables.
  - RLS Penetration Testing: Run SQL scripts verifying customer user tokens cannot read private admin or technician tables.

### Step 30: Production CI/CD Pipeline & App Store Release
- **Action:** Configure GitHub Actions CI/CD workflow.
  - Generate release Android App Bundle (`.aab`) signed with production keystore.
  - Generate release iOS `.ipa` signed with Apple Distribution Certificate.
  - Deploy production Supabase Edge Functions and migrate database to production cluster.
  - Submit to Google Play Store & Apple App Store.
